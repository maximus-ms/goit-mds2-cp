# Дипломний Проєкт: Система інтелектуальної діагностики технічних пристроїв на основі акустичних сигналів з використанням методів машинного навчання

## Тема Дипломної Роботи

**Система інтелектуальної діагностики технічних пристроїв на основі акустичних сигналів з використанням методів машинного навчання**

## Опис Проєкту

Цей дипломний проєкт присвячений розробці інтелектуальної системи діагностики технічних пристроїв на базі мікроконтролера **ESP32-S3** та **мікрофонної решітки** (на поточному етапі MVP — стерео-пара з 2 мікрофонів). Система використовує методи машинного навчання та просторової обробки акустичних сигналів для виявлення нештатних ситуацій та діагностики стану промислових механізмів (двигунів, насосів, вентиляторів, генераторів).

### Ключові Особливості

- **Edge AI**: Виконання інференсу моделі безпосередньо на мікроконтролері без необхідності підключення до хмари
- **Few-Shot Learning**: Система навчається на мінімальній кількості прикладів нормальної роботи (близько 10 секунд запису)
- **Просторова фільтрація**: Використання мікрофонної решітки для покращення співвідношення сигнал/шум та придушення завад
- **Універсальність**: Агностична до типу обладнання — працює з будь-яким механізмом після короткого навчання
- **Низька вартість**: Загальна вартість компонентів становить ~$18-20

### Технологічний Стек

- **Апаратна платформа**: ESP32-S3 (Xtensa LX7 з векторними інструкціями)
- **Мікрофони**: 2× I2S MEMS мікрофони (стерео-пара для MVP, з можливістю розширення до 4 мікрофонів)
- **Framework**: ESP-IDF (C/C++)
- **DSP**: esp-dsp (оптимізовані FFT та векторні операції)
- **ML**: ESP-DL або TensorFlow Lite Micro
- **Алгоритм**: Siamese Network / One-Class Classification з косинусною відстанню

### Алгоритм Роботи

#### Етап 1: Навчання та Калібрування (Enrollment)
1. Запис ~10 секунд акустичних сигналів нормальної роботи технічного пристрою
2. Розбиття на вікна та обробка через Feature Extractor для виділення характеристик
3. Обчислення центроїдного вектора нормального стану пристрою
4. Збереження еталонного вектора в енергонезалежну пам'ять (NVS/Flash)

#### Етап 2: Діагностика та Моніторинг (Inference)
1. Запис коротких аудіо фрагментів від технічного пристрою
2. Препроцесінг акустичних сигналів (обробка стерео сигналу з 2 мікрофонів, можливе застосування beamforming)
3. Обробка через ML модель для отримання вектора ознак
4. Порівняння з еталонним вектором через косинусну відстань
5. Діагностика стану пристрою та генерація сповіщення при виявленні відхилень

### Переваги Підходу

- ✅ Не потрібен великий розмічений датасет для кожного типу технічного пристрою
- ✅ Адаптивність до конкретного обладнання — система налаштовується під будь-який пристрій
- ✅ Працює в реальному або квазі-реальному часі для безперервної діагностики
- ✅ Покращення SNR завдяки використанню стерео-пари мікрофонів для просторової фільтрації та точнішої діагностики
- ✅ Просторова селективність для придушення завад та виділення сигналу від діагностованого пристрою

#### Код Проєкту (`project/`)

- **`dev/main/i2s_main.c`**  
  Основна прошивка для ESP32-S3:
  - Драйвер I2S у режимі Master Receiver
  - Буферизація даних через DMA з чергою
  - Запис даних у Flash пам'ять
  - Управління записом через кнопку BOOT
  - Конвертація 32-bit даних у 16-bit формат

- **`host/tools/bin2wav.py`**  
  Python-скрипт для конвертації бінарних даних у WAV:
  - Підтримка 16-bit та 32-bit форматів
  - Перевірка цілісності даних через CRC32
  - Нормалізація семплів для коректного відображення

- **`host/tools/get_wav_from_flash.sh`**  
  Bash-скрипт для автоматичного зчитування даних з Flash та конвертації у WAV формат

- **`host/tools/process_mimii.py`**  
  Python-скрипт для обробки датасету MIMII:
  - Завантаження багатоканальних WAV файлів у пам'ять
  - Виділення та агрегація важливих каналів для кожного типу машини
  - Мікшування вибраних каналів для отримання стерео-сигналу
  - Конвертація у формат int16 для економії пам'яті
  - Серіалізація оброблених даних у PyTorch формат (`.pt` файл)
  - CLI інтерфейс з підтримкою аргументів командного рядка

#### ML Інфраструктура (`project/host/ml/`)

- **`prepare_dataset.py`**  
  Універсальний скрипт для обробки датасетів:
  - Підтримка як MIMII датасету, так і кастомних датасетів з аналогічною структурою
  - Завантаження та обробка WAV файлів з уніфікованою логікою
  - Функція `load_and_process_wav_file` для передпідготовки аудіо файлів
  - Підтримка конфігурації через `.env` файл та змінні середовища
  - Структуроване логування через модуль `logging`

- **`triplet_memory_dataset.py`**  
  Клас даталоадера для тренування моделі:
  - Реалізація TripletMemoryDataset для формування тренувальних триплетів (anchor, positive, negative)
  - Статичний метод `create_mel_transform` для створення трансформ спектрограм
  - Підтримка abnormal семплів від тієї самої машини для покращення розпізнавання аномалій
  - Балансування між різними типами негативних семплів

- **`model.py`**  
  Архітектура моделі TinyAudioCNN:
  - Реалізація CNN моделі для детекції аномалій на основі MEL-спектрограм
  - Всі супутні компоненти та утиліти для ініціалізації моделі
  - Підтримка конфігурації через змінні середовища

- **`early_stopping.py`**  
  Клас для раннього зупинення тренування:
  - Підтримка різних критеріїв зупинки (patience, minimum loss threshold)
  - Функціональність збереження та відновлення найкращих ваг моделі
  - Структуроване логування процесу раннього зупинення

- **`train.py`**  
  Модуль тренування моделі з інтеграцією MLflow:
  - Повна інтеграція з MLflow для відстеження експериментів
  - Автоматичне логування параметрів, метрик та артефактів
  - Підтримка раннього зупинення через EarlyStopping
  - Збереження checkpoints, моделей, графіків та історії тренування
  - Режим тестування (`--test`) з автоматичною конфігурацією MLflow

- **`test.py`**  
  Модуль тестування та валідації моделі:
  - Повна інтеграція з MLflow для логування результатів валідації
  - Підтримка завантаження моделей з MLflow (URI, run_id) або локальних файлів
  - Тестування на різних датасетах (включаючи кастомні зібрані вручну)
  - Режим тестування двох WAV файлів (`--normal` та `--anomaly`) для швидкого тестування
  - Автоматичне збереження результатів валідації, метрик та гістограм в MLflow

  Файл з усіма необхідними залежностями для ML модулів (torch, torchaudio, soundfile, mlflow, boto3 тощо)

## Статус Проєкту

Проєкт знаходиться на етапі **реалізації MVP (Minimum Viable Product)**. 

**Завершено:**
- ✅ Фундаментальний аналіз технічної реалізованості системи інтелектуальної діагностики
- ✅ Визначено архітектуру системи та методологію машинного навчання
- ✅ Зібрано фізичний прототип на базі ESP32-S3 з двома I2S мікрофонами
- ✅ Реалізовано firmware для запису аудіо даних через I2S інтерфейс
- ✅ Розроблено інструменти для конвертації даних у WAV формат
- ✅ Налагоджено наскрізний пайплайн збору даних "Device-to-PC"
- ✅ Проведено перше демо та валідацію якості запису
- ✅ Знайдено та проаналізовано датасет MIMII для навчання моделей
- ✅ Розроблено пайплайн обробки датасету (завантаження, агрегація каналів, серіалізація у PyTorch формат)
- ✅ Оптимізовано використання пам'яті: зменшення обсягу даних у ~8 разів через вибір критичних каналів
- ✅ Проведено теоретичну підготовку: вивчення курсів з обробки аудіосигналів та deep learning
- ✅ Налаштовано MLflow інфраструктуру для відстеження експериментів (Tracking Server + MinIO/S3)
- ✅ Розроблено архітектуру CNN моделі TinyAudioCNN для детекції аномалій на основі MEL-спектрограм
- ✅ Створено DataLoader (TripletMemoryDataset) для завантаження оброблених даних та формування тренувальних триплетів
- ✅ Проведено навчання baseline моделі на датасеті MIMII
- ✅ Проведено тестування моделі в реальних умовах на 3D принтері
- ✅ Проведено друге демо з науковим керівником та отримано рекомендації
- ✅ Повна модуляризація ML інфраструктури (всі компоненти винесені в окремі модулі)
- ✅ Уніфікація обробки аудіо та впровадження структурованого логування
- ✅ Покращення стратегії тренування з використанням abnormal семплів
- ✅ Оптимізовано архітектуру моделі (Depthwise Separable Convolutions) та процес навчання (AdamW, LR Schedulers)
- ✅ Реалізовано та верифіковано обчислення Mel-спектрограм на ESP32 (ESP-DSP)
- ✅ Впроваджено гнучкі детектори аномалій (Mahalanobis, PCA) та стандартизацію дистанцій
- ✅ Створено інструменти візуалізації ембеддингів для аналізу якості моделі

**Поточний етап:**
- 🔄 Інтеграція TFLite Micro інференсу в прошивку ESP32
- 🔄 Системне тестування (End-to-End) повного циклу роботи
- 🔄 Підготовка до фінального демо

**Наступні кроки:**
- Конвертація моделі в TFLite формат та оптимізація
- Фінальні натурні випробування системи на реальному обладнанні
- Оформлення результатів та презентації
